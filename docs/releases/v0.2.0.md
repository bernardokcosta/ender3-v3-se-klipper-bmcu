# 0.2.0 pre-release: BMCU integration and multilingual stock display

Four BMCU channels feed the Ender 3 V3 SE's single physical extruder through
BMCU-Klipper 1.0.6, firmware 1.0.1 and `generic_single_extruder`.
The official installer remains responsible for BMCU modules and services.

## Changes

- Separate BMCU endpoint, sensor template and Ender filament configurations.
- Complete calibrated load/capture/nozzle feed/purge and cutter-free
  tip-forming/unload callbacks, blocking until motion finishes.
- Shared heating controller for screen extrusion and filament macros. Reuse
  an appropriate nozzle target or the selected PLA/PETG profile before motion.
  Cold-extrusion protection stays enabled.
- Cancellation, timeout/failure messages, repeated-click protection, G-code
  state restoration and calibrated speeds independent of print overrides.
- Pause/resume/cancel integration, with the busy guard before the official
  BMCU manual-refill resume hook.
- English by default; `language: pt_BR` in `[e3v3se_display]` selects Brazilian
  Portuguese after restarting Klipper. Code and documentation stay in English.
- Four channel actions and current/target temperatures, printer state and
  runtime-confirmed active channel. Missing/offline BMCU does not break menus.

## Validation

50 automated tests passed locally using the real Klipper G-code dispatcher,
macro engine and state handling, with simulated heaters, reactor and motion.
Checks cover cold extrusion, heating cancellation, repeated clicks, stale
timers, G-code restoration, speed overrides, BMCU disconnection, paused route
status, resume-hook ordering, 1,000 idempotent resume-guard installations and
legacy regex escaping with UTF-8 translation input.
Python compilation, whitespace and Git diff checks also passed.

The tag publication workflow builds the GD32F303 firmware, verifies its MCU
dictionary and runs the complete Klippy configuration regression before
attaching firmware, dictionary, defconfig, build metadata and SHA-256 checksums.
These software checks do not demonstrate physical acceptance.

## Installation and limitations

Use host source and MCU firmware from this exact tag. The target is the
physically identified GD32F303RET6 on the CR4NS200320C14 mainboard, with the
stock display; do not flash this build onto an STM32F401 board.

Filament load/unload is disabled until physical calibration is complete.
Measure the switch-to-gear distance and route limits; set the arrival mode,
load/purge distances and cutter-free tip-forming sequence for the assembly.
The supplied distances are unset, not universal defaults.

UART1 TX PG06/RX PG07 and switch NO PC9/COM GND are documented. Linux UART
paths and GPIO chip/offset must be identified on the installed Orange Pi
image. Do not substitute physical header numbers for GPIO line identifiers.

BMCU 1.0.6 motor stop does not fully cancel a host transport flow. Screen
cancellation latches the request, blocks subsequent extruder callbacks and
requests stop when the current transport phase returns. Wait for motion to
stop and inspect the route before recovery.

Physical channel tests, tip formation, switch arrival, heating/motion
cancellation, printer commissioning and display accents remain pending.

Read the [installation guide](https://github.com/bernardokcosta/ender3-v3-se-klipper-bmcu/blob/v0.2.0/docs/Ender3_V3_SE.md)
and [BMCU configuration/calibration guide](https://github.com/bernardokcosta/ender3-v3-se-klipper-bmcu/blob/v0.2.0/docs/Ender3_V3_SE_BMCU.md)
before use.

No BMCU firmware image or proprietary stock-display binary is bundled.
